## 第一部分 · 修订背景：v1 的归因错了

v1 把启动白屏的主因归给 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，并据此把「窗口防截屏」列为禁止项、把整份设计改写成「以检测为主的报告」。复盘后这个归因不成立。

### 1.1 白屏的真正根因

`lib.rs` 的 `setup()` 里同步调用 `commands::agent::bootstrap_git_agent`，它走到 `agent::ensure()` → `probe_existing_git_agent()`。该函数把 `~/.ssh/agent` 下**每一个**文件外加 `SSH_AUTH_SOCK` 都拿去跑一次 `ssh-add -l`，而当时 `run_ssh_add` 用的是无超时的 `wait_with_output()`。

`setup()` 跑在主线程、且在事件循环开始泵消息之前。只要任何一次 `ssh-add -l` 连上一个「文件还在、进程已卡死」的 agent 套接字，窗口就创建了却永远不会被绘制——症状正是**纯白 + 标题栏「未响应」**。

触发条件在**机器状态**里，不在仓库里：

- 累积的孤儿 `ssh-agent.exe` 进程；
- `~/.ssh/agent` 下越积越多的残留套接字文件；
- 指向已消失套接字的用户级 `SSH_AUTH_SOCK` 环境变量。

这解释了 v1 排查中两个最关键、当时无法解释的现象：

| 现象 | 原因 |
|---|---|
| `git reset --hard 8d61ab2` 后白屏依旧 | 卡死条件是磁盘残留 + 在跑的孤儿进程，回滚代码碰不到 |
| 重启电脑后恢复正常 | 重启杀掉全部孤儿 agent；剩下的套接字没人听，`ssh-add` 立刻失败返回 |

复盘时实测：重启后逐个探测残留套接字耗时 23ms / 25ms / 116ms，均为健康的快速返回。故障态已随重启消失，无法再复现，但证据链完整。

### 1.2 WDA 的定性订正

`SetWindowDisplayAffinity` 是进程内的 per-HWND 状态，进程退出即失效，不可能跨 `git reset --hard` 存活；而白屏在 WDA 代码被完全删除后依然存在。它也是显示层 API，**不可能堵住消息泵、不可能让进程 `Responding=False`**。v1 §6.5 的信号表把「白」和「未响应」当成同一症状归因，是判断跑偏的起点。

v1 那句「即便改回 `WDA_NONE`，只要启动路径调用过一次 Exclude，首屏就会废掉」，是在 ssh-agent 卡死这个混淆变量全程存在的情况下得出的推论，不是受控实验结论。

**结论：WDA 从「已证实的禁止项」降级为「未验证、待隔离实验」。** 见第九部分。在实验出结论前不落地，但也不再作为砍掉硬防护方向的依据。

### 1.3 `--disable-gpu` 同样存疑

当前工作区里未提交的 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = --disable-gpu --disable-gpu-compositing`，基于同一个「GPU 合成上不了屏」假设加入，也未隔离验证。既然真因是主线程被堵，它很可能是白交的性能税——本应用有开门动画与进场动画，强制软件渲染会明显掉帧。

**处理：撤回默认启用**，改为仅在环境变量 `GAM_DISABLE_GPU=1` 时附加，作为兼容性兜底。

### 1.4 v1 的方案性问题

除了归因，v1 的方案本身也有两处方向性错误：

1. **威胁模型和对策对不上。** v1 说要防「剪贴板监听偷验证码」，给出的对策却是「扫描进程名，发现 `ditto.exe` 就提示用户」。而本应用当前 `clipboard_write` 就是一句 `arboard::set_text`，复制出去的每个验证码和密码都会进 Win+V 历史、同步到云剪贴板、被剪贴板管理器抓走，且 20 秒后的 `clipboard_clear` **清不掉历史里那一份**。真正该做的是写入时打排除标记（见 5.2），成本几十行，收益远高于进程名扫描。
2. **大量检查项在普通权限下必然输出「无法确定」**，构成噪音。详见第十一部分的已否决清单。

## 第二部分 · 目标与范围

### 2.1 功能目标（v2）

| 编号 | 目标 |
|---|---|
| S1 | 修复启动路径上的 ssh-agent 套接字泄漏与主线程阻塞（前置项，与安全模块解耦） |
| S2 | 复制机密到剪贴板时，阻止其进入剪贴板历史、云剪贴板与第三方剪贴板监听 |
| S3 | 在设置页提供「安全自查清单」：工作区落盘位置 + 应用自身防泄漏开关的启用状态 |
| S4 | 清单如实写明能力边界，尤其是系统不提供枚举剪贴板监听者 / 截屏调用方的能力 |
| S5 | 全程本机、零遥测、不落盘敏感细节 |
| S6 | Windows 首发；macOS / Linux 留接口并降级 |

### 2.2 非目标（明确不做）

在 v1 原有非目标之上，v2 新增三条**已评估后否决**的：

- **不做进程名扫描。** 检不出真木马（木马不会叫 `anydesk.exe`），却会稳定误伤用户自己故意开的 OBS / ToDesk / Ditto，还要维护一份会腐烂的特征库。
- **不做系统基线体检**（Defender / BitLocker / OS Build / 系统代理）。普通权限下大多只能输出「无法确定」。
- **不做 0–100 数字评分。** 分数取决于恰好实现了多少检查项，加一项所有人的分都变，且会诱导用户刷分而不是看建议。改为三档状态 + 待办清单。

v1 原有非目标继续有效：不实时监控截屏/剪贴板调用方；不读其他进程的命令行、内存、打开文件；不装全局钩子、不提权、不装驱动；不上传任何数据。

### 2.3 遵循的安全准则

| 原则 | 出处 | 在本功能中的落法 |
|---|---|---|
| 数据最小化 | ISO 27001 / GDPR Art.5 | v2 已不再枚举任何其他进程 |
| 本地处理 | 数据驻留 | 结果仅内存与本机配置；不上云 |
| 最小权限 | Least Privilege | 全部检查项在普通用户权限下可完成，否则不做 |
| 纵深防御 + 透明知情 | 安全工程常识 | 以硬防护为主、提示为辅；UI 标明做不到的事 |

## 第三部分 · 能力边界（UI 必须如实转述）

用户态下 Windows **不会**向外广播「哪个进程调用了 `AddClipboardFormatListener` / `BitBlt` / `Windows.Graphics.Capture`」。因此：

| 用户担心的事 | v2 能做的 | 做不到的 |
|---|---|---|
| 有程序在听剪贴板 | 写入时打排除标记，让**守规矩的**监听者与系统历史不记录 | 阻止刻意无视标记的恶意程序；指认监听者 |
| 有程序在截屏/录屏 | —（本版不做） | 指认「刚才是谁截的屏」 |
| 木马偷 TOTP | 剪贴板排除 + 限时清空 + 查看前二次验证 + 失焦锁定 | 把主窗口从所有截图里涂黑（待验证，见第九部分） |

排除标记是**协作式**机制：它是给系统剪贴板历史、云剪贴板和守规矩的剪贴板管理器看的约定。恶意程序可以无视。UI 不得把它描述成「防木马」。

## 第四部分 · 本版落地内容

### 4.1 P0-A｜启动稳定性（前置，与安全模块解耦）

这一档必须先落，否则第 1.1 节的白屏会随使用次数增加而复发——即使加了超时，N 个残留套接字也会把启动拖成 N × 超时。

| 项 | 现状 | 目标 |
|---|---|---|
| `bootstrap_git_agent` | 已改后台线程（工作区未提交） | 保留；`setup()` 不得再加任何同步工作 |
| `ssh-add` / `ssh-agent` 超时 | 已加 8s（工作区未提交） | 保留 |
| `vault_try_grace_unlock` | 已改为延后触发云同步（工作区未提交） | 保留 |
| **固定套接字复用失效** | **未修** | `start_git_agent` 的 `-a` 未真正落到 `~/.ssh/agent/git-keymaster`，导致每次启动都新起 agent、留新文件 |
| **目录遍历无上限** | **未修** | `probe_existing_git_agent` 遍历整个目录，文件越积越多 |
| **孤儿 agent 回收** | **未修** | `git-keymaster.pid` 记录的上一个 agent 从不回收 |
| **陈旧 `SSH_AUTH_SOCK`** | **未修** | 用户级环境变量指向已消失的套接字后永久有效，构成长期陷阱 |
| `--disable-gpu` | 默认启用（工作区未提交） | 改为仅 `GAM_DISABLE_GPU=1` 时附加 |

修复要点：

- 先验证 `-a <msys 路径>` 在当前 Git for Windows 版本上的真实落点，据此确定是继续用 `-a` 还是改为启动后按 `ssh-agent -s` 输出记账。
- `probe_existing_git_agent` 按 mtime 倒序、**最多探测 3 个**候选；其余直接跳过。
- 启动时按 pid 文件回收上一个 agent；清理 mtime 超过 7 天且无进程持有的套接字文件。
- 写用户级 `SSH_AUTH_SOCK` 前先校验目标存在；探测失败时主动清掉这个变量。

### 4.2 P0-B｜剪贴板排除（本版核心硬防护）

复制机密时，除 `CF_UNICODETEXT` 外在**同一个剪贴板会话内**追加三个注册格式：

| 注册格式名 | 数据 | 作用 |
|---|---|---|
| `ExcludeClipboardContentFromMonitorProcessing` | 空 / 1 字节 | 请求剪贴板监听者不要处理本次内容 |
| `CanIncludeInClipboardHistory` | `DWORD 0` | 不进 Win+V 剪贴板历史 |
| `CanUploadToCloudClipboard` | `DWORD 0` | 不同步到云剪贴板 |

实现约束：

- **不能继续用 `arboard::set_text`**——它自己开关剪贴板会话，无法在同一会话里追加格式。机密路径需走原生：`OpenClipboard` → `EmptyClipboard` → `SetClipboardData(CF_UNICODETEXT, ...)` → 三个 `SetClipboardData(fmt, ...)` → `CloseClipboard`。
- `OpenClipboard` 会因其他进程占用而失败，需少量重试（如 5 次 × 20ms）后放弃并回退到普通写入 + 提示。
- 写入用的 `GlobalAlloc` 缓冲交给系统后不得再释放；本地明文副本用 `zeroize` 抹掉（仓库已有 `zeroize` 依赖）。
- 非机密复制（如公钥、别名）继续走 `arboard`，不必排除。
- `clipboard_clear` 改为**先比对 `GetClipboardSequenceNumber`**，只在剪贴板内容仍是我们写入的那份时才清空，避免误清用户随后复制的东西。
- macOS / Linux 无对应机制，降级为普通写入，清单里如实标注。

`windows-sys` 需追加：`Win32_System_DataExchange`、`Win32_System_Memory`。

### 4.3 P0-C｜安全自查清单（storage + app）

只保留两类**普通权限下必然有确定结论**的检查项。

**落盘 storage**

- 工作区路径是否位于同步盘。**直接复用 `commands::vault::check_workspace_path` 的关键词表**（onedrive / dropbox / google drive / icloud / 坚果云 / nutstore / 百度网盘），不得另起一套。

**应用防护 app**（读 `AppConfig`，全部可一键跳转到对应设置）

| 字段 | 判定 |
|---|---|
| `clipboard_clear_seconds == 0` | `warn`：复制后不会自动清空 |
| `reveal_grace_minutes` 偏长 | `info`：免密窗口较长 |
| `lock_on_sleep == false` | `info`：休眠/锁屏时不会自动锁定 |
| `auto_lock_minutes` 偏长或为 0 | `info`：自动锁定窗口较长 |
| 剪贴板排除是否生效（平台能力） | `ok` / `info`（非 Windows 降级） |

清单是**纯配置读取**，无外部命令、无进程枚举、无网络，因此可以同步计算、随时刷新，不需要后台扫描线程，也不需要 `security-report` 事件。这一点比 v1 的架构简单得多。

## 第五部分 · 报告模型

```ts
type SecuritySeverity = "ok" | "info" | "warn";
type SecurityLevel = "safe" | "caution" | "risk";
type SecurityCategory = "storage" | "app";

interface SecurityFinding {
  id: string;
  category: SecurityCategory;
  severity: SecuritySeverity;
  title: string;
  detail: string;
  advice: string;
  /** 跳转到对应设置项的锚点，null 表示无法一键处理 */
  settingsAnchor?: string | null;
  limitation?: string | null;
}

interface SecurityChecklist {
  checkedAt: string;   // ISO
  level: SecurityLevel;
  items: SecurityFinding[];
}
```

**无 `score` 字段。** 等级由最严重项直接决定：存在 `warn` → `risk`；否则存在 `info` → `caution`；否则 `safe`。这样等级含义稳定，不随检查项数量漂移。

UI 呈现为一份待办清单：每条给出「问题 + 建议 + 一键前往设置」，`ok` 项折叠。

## 第八部分 · 工程约束（必守）

### 8.1 启动路径

- `setup()` 内**禁止**任何同步的进程启动、外部命令、网络、文件系统扫描。
- 任何 `Command` 调用必须走 `sys::run_timeout`；`sys::run` 的 30s 默认值只适用于用户主动触发的操作，不适用于启动路径。
- `vault_try_grace_unlock` 必须在返回前完成，云同步一律延后。
- 启动路径**不得**访问 HWND，不得在持有 `config` 锁时做重活。

### 8.2 归因纪律

v1 的教训是**在混淆变量存在时下了结论**。后续排查启动问题时：

| 信号 | 含义 |
|---|---|
| 进程 `Responding=False` | 主线程/消息泵被堵。**显示层 API 不会造成这个**，往阻塞调用上查 |
| 进程 `Responding=True` 但窗口全白 | 才是渲染/合成问题 |
| DevTools 端口无响应 | 通常是主线程堵住带累，不等于前端问题 |
| 浏览器开 `localhost:5173` 正常，只有 Tauri 窗口白 | 问题在 WebView2 宿主，不在 React |

`Responding` 对无边框窗口不完全可靠，需结合启动日志。**一次只改一个变量**，否则不得写入结论。

## 第九部分 · 待验证实验：WDA_EXCLUDEFROMCAPTURE

v1 把它定成禁止项，依据不足（见 1.2）。它是本应用唯一可能的「硬防截屏」手段，值得在真因已清楚的现在单独测一次。

**实验设计**（独立分支，不合入）：

1. 基线：当前 `main` + P0-A 修复，确认启动正常、`Responding=True`、动画流畅。
2. 变量只加一个：在窗口 `Ready` 之后（**不在 `setup()` 里**）对主窗口顶层 HWND 调用一次 `WDA_EXCLUDEFROMCAPTURE`。
3. 记录：窗口是否仍正常绘制、`Responding`、系统截图是否为黑、动画帧率。
4. 分别在 GPU 合成开启与 `GAM_DISABLE_GPU=1` 两种模式下各跑一次——这一步同时能回答 1.3 的疑问。
5. 改回 `WDA_NONE`，确认可逆。

**可能结论与去向：**

| 结果 | 处理 |
|---|---|
| 正常绘制 + 截图变黑 | 作为「查看机密时临时启用」的可选硬防护进入 P1 |
| 仅在 GPU 合成下白屏 | 记录为驱动相关，作为需要 `--disable-gpu` 的可选项，默认关 |
| 两种模式都白屏 | 此时才可正式定为禁止项，并转向「独立原生 HWND 弹层」方案 |

在实验出结论前，代码里不保留任何 `SetWindowDisplayAffinity` 调用。

## 第十部分 · 验收

### 10.1 P0-A 启动稳定性

## 第十一部分 · 后续版本候选与已否决项

### 11.1 P1（下一版考虑）

`session` 四项，全部是一次系统调用或一次注册表读，无超时风险、结论确定：

- `GetSystemMetrics(SM_REMOTESESSION)`：远程会话中 → 屏幕正被通道传走。
- 管理员令牌 `TokenElevation`：以管理员运行 → 违反最小权限。
- 注册表 `fDenyTSConnections`：RDP 入站是否允许。
- 注册表 `EnableLUA`：UAC 是否开启。

这四项落地后，检查项数量才够支撑一个独立的「安全中心」页面。

另外，第九部分的 WDA 实验若结论为正面，「查看机密时临时防截屏」也进 P1。

### 11.2 已否决（记录原因，避免重复提案）

| 项 | 否决原因 |
|---|---|
| 进程名扫描（远控/录屏/剪贴板工具） | 检不出真木马，稳定误伤用户自用工具，特征库会腐烂 |
| Defender 实时防护 | 真实状态键受篡改防护、普通权限读不到；策略键正常机器上不存在，「不存在 ≠ 已开启」。且第三方杀软场景下 Defender 关闭是正常的。若将来一定要做，只能用 `wscapi.dll` 的 `WscGetSecurityProviderHealth` |
| BitLocker 状态 | `manage-bde -status` 需管理员权限，不提权基本直接报错，加超时也只是更快地得到「无法确定」 |
| OS 版本 / Build 提示 | 砍掉 WDA 承诺后，「系统偏旧」对用户不产生任何可执行动作 |
| 系统代理 `ProxyEnable` | 本应用自带网络代理设置，用户常有意开代理，标记为风险即噪音 |
| `IsDebuggerPresent` 反调试 | 真实攻击者可轻易绕过；只能发现「随手挂了个调试器」，价值低于其带来的复杂度 |
| 0–100 数字评分 | 分值随实现的检查项数量漂移，诱导刷分而非看建议 |
| 后台扫描线程 + `security-report` 事件 | v2 检查项已收敛为同步配置读取，不需要 |
