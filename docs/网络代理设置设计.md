# 网络代理设置设计

> 配套文档：`程序更新功能设计.md`（自更新走 GitHub）、`发布新版本流程.md`
> 本文定位：部分地区访问 GitHub / GitLab 不稳定时，允许用户为本应用配置代理，使**检查更新、平台 API、Git HTTPS、SSH 远程**走同一套代理。
> 制定日期：2026-09-10
> 状态：已实现（N1–N7）

---

## 第一部分 · 目标与范围

### 1.1 要解决什么

本应用访问外部平台的路径不止一条：

| 通道 | 典型场景 | 不通时代价 |
|---|---|---|
| 应用内 HTTPS（reqwest） | GitHub PAT 校验 / 拉组织 / 上传公钥；预发布通道读 Releases API | 平台功能失败 |
| Tauri 更新插件 HTTPS | 拉 `latest.json`、下载安装包 | 检查更新失败、无法应用内升级 |
| `git` HTTPS | 用户用 `https://github.com/...` 克隆 | clone 失败 |
| SSH（本应用主力） | `git clone git@<Host别名>:...`、`ssh -T` 体检 | 克隆与连通性检查失败 |
| 云同步 HTTPS | R2 / S3 | 备份恢复失败（端点可能本就可达，做成可关） |

只给「浏览器设系统代理」不够：应用内 `reqwest`、`tauri-plugin-updater`、子进程 `git`/`ssh` **不会自动吃系统代理**（除非碰巧有环境变量，且更新插件默认也不保证跟环境走）。

### 1.2 功能目标

| 编号 | 目标 |
|---|---|
| P1 | 设置页可配一条代理：HTTP / HTTPS / SOCKS5，可选账号密码，可开关。 |
| P2 | 开启后，本应用发出的平台 HTTPS（GitHub / GitLab API、更新检查与下载）走该代理。 |
| P3 | 开启后，本应用拉起的 `git` HTTPS 请求走该代理。 |
| P4 | 开启后，本应用拉起的 `ssh` / `GIT_SSH_COMMAND` 经 ProxyCommand 走该代理（本应用克隆以 SSH 为主，这一条是刚需）。 |
| P5 | 云同步默认也走同一代理，可单独关掉（国内 R2/S3 往往不需要）。 |
| P6 | 「测试代理」一键探测 GitHub HTTPS 是否通；SSH 助手缺失时给出明确提示，不静默失败。 |

### 1.3 非目标（本期不做）

- 不写进用户手写的 `~/.ssh/config` 托管区块（与现有「不接管用户 config」一致）。代理只在**本应用拉起的进程**上注入。
- 不做分流规则 / PAC / 按域名白名单（`NO_PROXY` 可后置）。
- 不做系统级代理、不改用户机器的 `HTTP_PROXY` 用户环境变量。
- `open_url` 打开的系统浏览器不走本设置（浏览器用系统/扩展代理）。
- 不做代理密码进保险库：代理是本机偏好，须在解锁前/后都能读；明文落在 `%APPDATA%\git-keymaster\config.json`，界面提示风险。
- 不做企业 MITM 自定义 CA 导入。

## 第二部分 · 配置模型

放 `AppConfig`（`app_config.rs`），与更新源一样属于本机偏好，`#[serde(default)]` 平滑升级。

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub struct NetworkProxy {
    /// 总开关。false 时其余字段保留但不生效。
    pub enabled: bool,
    /// "http" | "https" | "socks5"
    pub scheme: String,
    pub host: String,
    pub port: u16,
    #[serde(default)]
    pub username: Option<String>,
    #[serde(default)]
    pub password: Option<String>,
    /// 本应用拉起的 git HTTPS 是否带上代理环境变量。默认 true。
    #[serde(default = "default_true")]
    pub apply_to_git_https: bool,
    /// 本应用拉起的 ssh / GIT_SSH_COMMAND 是否注入 ProxyCommand。默认 true。
    #[serde(default = "default_true")]
    pub apply_to_ssh: bool,
    /// 云同步 reqwest 是否走代理。默认 true；国内对象存储可关。
    #[serde(default = "default_true")]
    pub apply_to_cloud_sync: bool,
}
```

`AppConfig` 新增：

```rust
#[serde(default)]
pub network_proxy: Option<NetworkProxy>,
```

`None` 或 `enabled: false` = 不干预，保持现状（reqwest / 更新插件用各自默认；git/ssh 不额外设环境变量）。

### 2.1 URL 拼装（内部统一）

校验：

- `scheme` ∈ {`http`, `https`, `socks5`}
- `host` 非空，禁止空格与 URL 分隔符
- `port` ∈ 1–65535
- 用户名/密码做百分号编码后再写入 URL

拼出的代理 URL 形如：

```
http://127.0.0.1:7890
socks5://user:pass@127.0.0.1:7890
```

所有通道共用这一条 URL，避免各模块各拼一套。

## 第三部分 · 生效通道

统一模块 `net/proxy.rs`（新建），对外只暴露：

| 函数 | 用途 |
|---|---|
| `effective(cfg) -> Option<NetworkProxy>` | 总开关关闭则 None |
| `proxy_url(p) -> Result<Url>` | 校验并拼 URL |
| `apply_reqwest(builder, p)` | `ClientBuilder::proxy(Proxy::all(url))`；开启时先 `no_proxy()` 再挂本代理，避免和环境变量叠两层 |
| `apply_updater(builder, p)` | `UpdaterBuilder::proxy(url)`（官方已支持） |
| `apply_git_command(cmd, p)` | 按开关写 `HTTP(S)_PROXY` / `ALL_PROXY`（大小写各一份） |
| `apply_ssh_command(cmd, p)` | 按开关追加 `-o ProxyCommand=...` |
| `ssh_helper_status() -> SshProxyHelper` | 探测本机可用的 connect / ncat |
| `test_github_https(p) -> Result<u128>` | 经代理 GET `https://github.com`，返回耗时毫秒 |

### 3.1 应用内 HTTPS（P2）

现有分散的客户端全部改为走工厂，禁止再 `Client::new()` / 无代理 `builder().build()`：

| 现状 | 改为 |
|---|---|
| `git/github.rs` 的 `client()` | `net::http::blocking_client(cfg)` |
| `update/checker.rs` 预发布 `reqwest::Client::new()` | `net::http::async_client(cfg)` |
| `sync/s3.rs` 的 `S3Client::new` | 若 `apply_to_cloud_sync` 则挂代理 |

`reqwest` 需打开 `socks` feature，否则 SOCKS5 无法用：

```toml
reqwest = { version = "0.12", default-features = false, features = ["rustls-tls", "json", "blocking", "socks"] }
```

### 3.2 更新插件（P2）

`update/checker.rs` 与 `commands/update.rs` 里现有的 `updater_builder()` 追加：

```rust
let mut b = app.updater_builder().timeout(...).endpoints(...)?;
if let Some(p) = effective_proxy {
    b = b.proxy(proxy_url(&p)?);
}
```

检查与下载安装必须走同一套 builder，否则「能看到更新、下不下来」。

### 3.3 Git HTTPS（P3）

`commands/repo.rs` 的 `run_git` 在现有 `GIT_SSH_COMMAND` 逻辑旁调用 `apply_git_command`：

```
HTTPS_PROXY / HTTP_PROXY / ALL_PROXY
https_proxy / http_proxy / all_proxy
```

只影响本应用拉起的那次 `git`，不改用户全局 git config。

### 3.4 SSH（P4）——本应用的主力路径

克隆默认改写成 `git@<Host别名>:`，**只设 HTTP 代理救不了 SSH**。

策略：运行时注入，不改托管 config。

1. 探测助手（按序）：
   - 与当前 `git` 同发行版的 `connect.exe` / `connect`（Git for Windows 常见）
   - `ncat`（Nmap）
   - PATH 上的 `connect`
2. 拼 `ProxyCommand`：
   - HTTP/HTTPS 代理 + `connect`：`"<connect>" -H <host>:<port> %h %p`
   - SOCKS5 + `connect`：`"<connect>" -S <host>:<port> %h %p`
   - SOCKS5 + `ncat`：`"<ncat>" --proxy-type socks5 --proxy <host>:<port> %h %p`
   - HTTP + `ncat`：`"<ncat>" --proxy-type http --proxy <host>:<port> %h %p`
3. 注入点：
   - `run_git` 已写的 `GIT_SSH_COMMAND` 末尾追加 `-o ProxyCommand="..."`
   - `test_connection`（`ssh -T`）同样追加
4. 助手缺失：`apply_to_ssh` 视为失败并在「测试代理」里写明「HTTPS 可用，但 SSH 需要 Git for Windows 的 connect 或 ncat」。不把残缺命令塞进 ssh。

本期不做：把用户名密码传给 `connect`/`ncat` 的完整认证矩阵（常见本地Clash/V2Ray 无认证）。若代理要认证且用户开了 SSH，界面提示「SSH 通道暂不支持带用户名密码的代理，请改用本机无认证端口或只开 HTTPS」。

### 3.5 云同步（P5）

`S3Client::new` 读取 `apply_to_cloud_sync`。默认跟随总开关，避免「GitHub 通了、备份仍超时」时用户不知道还有第二跳。

## 第四部分 · IPC 与界面

### 4.1 命令

| 命令 | 签名 | 作用 |
|---|---|---|
| `get_network_proxy` | `() -> Option<NetworkProxy>` | 读配置（密码原样返回给本机设置页） |
| `save_network_proxy` | `(proxy: Option<NetworkProxy>) -> ()` | 校验后保存；`None` 清空 |
| `test_network_proxy` | `(proxy: NetworkProxy) -> ProxyTestResult` | 用**表单里尚未保存**的值探测，便于先测后存 |

```ts
export interface ProxyTestResult {
  httpsOk: boolean;
  httpsMs: number | null;
  httpsError: string | null;
  sshHelperFound: boolean;
  sshHelperName: string | null;
  sshNote: string | null; // 助手缺失或认证不支持时的说明
}
```

### 4.2 设置页

放在 **关于与更新** 分栏，紧挨「更新偏好与数据源」：用户检查更新失败时最先想到这里。

卡片「网络代理」：

- 总开关
- 协议下拉：HTTP / HTTPS / SOCKS5
- 主机、端口
- 用户名、密码（可选，密码框）
- 三个子开关：Git HTTPS、SSH、云同步（默认开）
- 「测试连接」→ 展示 GitHub HTTPS 是否通、耗时、SSH 助手状态
- 「保存」

文案要点：代理只作用于本应用发起的请求，不改系统代理；SSH 依赖本机 `connect`/`ncat`。

## 第五部分 · 安全与健壮性

| 关注点 | 措施 |
|---|---|
| 密码落盘 | 本机 `config.json`，权限沿用现有文件；日志与错误字符串剥离 userinfo |
| 输入校验 | 非法 scheme/host/port 拒绝保存 |
| 叠加代理 | 启用本设置时 reqwest `no_proxy()` 再挂指定代理 |
| 测试失败 | 不自动改配置；检查更新失败文案可提示「若无法访问 GitHub，请到网络代理」 |
| 与自定义更新源 | 代理与更新源正交：换 Gitee/内网清单仍可走代理，也可关代理直连内网 |
| 旧配置 | 缺字段 = 无代理，行为与今天一致 |

## 第六部分 · 任务拆解

| 序 | 任务 | 交付物 | 验收 |
|---|---|---|---|
| N1 | `NetworkProxy` 配置 + 单测 | `app_config.rs` | 旧 `config.json` 无损加载 |
| N2 | `net/proxy.rs` URL / 助手探测 / 测试 | 模块 + 单测 | 三种 scheme 拼 URL 正确；非法输入报错 |
| N3 | reqwest 工厂替换 github / checker / s3 | 三处客户端 | 开代理后 PAT 与预发布检查走代理 |
| N4 | UpdaterBuilder 挂 `.proxy()` | `checker.rs` / `update.rs` | 开代理后能拉到 `latest.json` 并下载 |
| N5 | `run_git` / `test_connection` 注入 | `repo.rs` / `assets.rs` | HTTPS clone 与 SSH clone/`ssh -T` 走代理 |
| N6 | IPC + 设置页卡片 | `commands` / `ipc.ts` / `Settings.tsx` | 可测、可存、可关；密码不出现在普通日志 |
| N7 | reqwest `socks` feature | `Cargo.toml` | SOCKS5 实测可连 |

**验收主线**：在 GitHub 直连失败的网络里，填入本机 HTTP 或 SOCKS5 代理 → 测试连接成功 → 检查更新能读到 `latest.json` 的 `notes` → 用 SSH 别名克隆 GitHub 仓库成功。关掉代理后行为回到直连。

## 附录 · 关键决策

- **一条代理打所有平台通道**，不做「GitHub 一个、GitLab 一个」。
- **SSH 必须做**：本应用克隆改写为 SSH，只做 HTTP 代理等于没解决主路径。
- **运行时注入、不改 ssh config**：避免污染用户手写配置，也避免和托管区块抢 `ProxyCommand`。
- **更新插件用官方 `.proxy()`**，不手写下载器。
- **云同步默认同走、可关**，减少「一半通一半不通」的排障成本。
