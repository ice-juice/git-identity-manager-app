### 2.2 Rust 分层与依赖方向

```
commands/ (Tauri IPC 层，薄)
   │  只做参数校验 + 编排 + 结果映射；绝不在此写机密逻辑
   ▼
领域服务：vault / ssh / agent / git / sync
   │  互相之间通过 trait/接口解耦
   ▼
基础设施：store（加密存储）/ platform（平台操作）/ util
```

**硬性约束**：
- 机密（私钥明文、口令、PAT、恢复密钥、主密钥）**只存在于 Rust 侧内存**，用 `zeroize` 管理，**绝不跨 IPC 传到前端**。前端只拿到"是否解锁、指纹、公钥、状态灯、脱敏后的展示值"。
- 平台判断只允许出现在 `platform/` 内，业务代码禁用 `cfg!(windows)`。
- 所有会改动系统状态的操作，必须先产出"将执行的命令 / 将写入的 diff"供前端预览（透明性原则）。

## 第四部分 · 里程碑详细拆解

> 时间为单人全职估算。每个里程碑结束时应用**均可运行、可演示**。

### M1 · vault 内核与应用地基（约 1.5 周）

**目标**：把"加密工作空间"这个所有数据的容器建好；应用能初始化、解锁、锁定。这是后续一切数据落盘的前提，必须最先做。

**前置**：无（M0 已完成）。

**任务清单**：
1. 整改脚手架占位项（§1.2 全部）；`git init` + `.gitignore`（忽略 `node_modules`、`target`、`dist`、`*.enc`、真实工作空间路径）。
2. 前端接入 Tailwind + 路由 + 状态管理 + UI 组件库；清空默认模板，建立"锁定页 / 主框架 / 设置"三个骨架页。
3. 定稿 `vault.json` 头部结构与全部**子密钥派生标签**（含同步用标签，即使 v1.1 才用——避免日后不兼容）。
4. 实现信封加密：Argon2id（密码信封）+ HKDF（恢复信封）双信封包裹主密钥 MK；XChaCha20-Poly1305 加解密。
5. Argon2id **运行时标定**：初始化时按机器实测选参（目标 350–700ms，上限 512MiB，下限 19MiB/2），写入头部。
6. 恢复密钥：256-bit 随机 → Crockford Base32 + 版本前缀 + 校验组；生成、展示（复制/导出/二维码）、**分组逐段校验**输入。
7. 初始化向导五步（选目录含同步盘检测告警 / 设访问密码含强度指示 / 展示恢复密钥 / 强制回填校验 / 预留导入入口）。
8. 解锁 / 锁定 / 自动锁定（默认 15 分钟；可选休眠即锁）；失败递增延迟。
9. `zeroize` 贯穿 MK 与派生密钥；日志脱敏骨架；审计日志骨架。

**新增依赖**：见第三部分 M1 行。

**交付物**：可初始化工作空间、生成并校验恢复密钥、解锁/锁定、改密码、轮换恢复密钥的可运行应用。

**验收标准**：
- 初始化后 `vault.json` 内无任何明文机密；断电式强杀后重开能正常解锁。
- 错误密码解锁失败且触发递增延迟；恢复密钥能解锁（模拟忘记密码）。
- 改密码为毫秒级（不重加密数据）；轮换恢复密钥后旧密钥失效。
- 单元测试覆盖：KDF 派生确定性、加解密往返、篡改被拒、恢复密钥编解码与纠错。

**风险**：Argon2id 低配机偏慢——由标定兜底。

### M2 · 只读视图 + 外部密钥导入入库（约 1.5 周）

**目标**：把现有 ssh 资产**读出来体检**，并把散落的密钥**加密收编进 vault**。全程只读系统、不改 `~/.ssh`（导入是拷贝进 vault）。

**前置**：M1（vault 可用）。

**任务清单**：
1. `~/.ssh/config` 结构化解析（Host 块、`IdentityFile`、`IdentitiesOnly` 等），双视图（原文/结构化）。
2. 密钥扫描：`~/.ssh` + config 中引用到的外部路径；解析类型、指纹、有无口令、公钥。
3. ssh 工具链探测（落地 M0-5）：识别 System32 与 Git 两套 ssh、当前 git 实际调用哪个，界面展示并可选择。
4. agent 状态只读查询（服务态 + Git fallback 探测）。
5. 连接体检 `ssh -T`：解析 `Hi <name>`，与身份预期账号比对；`-o BatchMode=yes -o StrictHostKeyChecking=accept-new` 防卡死。
6. 身份总览 UI：四色状态灯（密钥/配置/Agent/连通），只读。
7. **外部密钥导入**：单文件/批量扫描/拖拽/粘贴；OpenSSH/PEM/PPK（检测提示转换）；配对校验（私钥推公钥比对）；带口令则要求输入并存入 vault；查重；RSA<2048 告警。
8. 导入落库：私钥加密写入 `keys/<id>.enc`，元数据写 `identities.enc`；原文件处置询问（保留/移入擦除/仅收紧权限）。
9. config 缺陷诊断（只提示不改）：缺 `IdentitiesOnly yes`、孤儿 `IdentityFile`、Host 重名。

**新增依赖**：`ssh-key`、`tempfile`。

**交付物**：能导入现有三个 Host 与散落密钥、加密入库、给出体检报告的应用（此时零写入 `~/.ssh`，零风险）。

**验收标准**：
- 能解析用户现有 config（含自建 `ssh.boxexchanger.net` 与三段路径场景）。
- 导入一把带口令密钥后，vault 内可通过二次验证查看其公钥与指纹；口令未明文落盘。
- 体检能正确标出 `Host github.com` 缺 `IdentitiesOnly yes`。
- `.ppk` 文件给出转换提示。

**风险**：PPK 转换依赖 puttygen——检测缺失并提示。

### M3 · 写操作 + 新建身份向导（约 1.5 周）

**目标**：开始安全地改文件；用向导脱离终端完成笔记步骤 1–6。

**前置**：M2。

**任务清单**：
1. config 托管区块机制（`# BEGIN/END managed by ...`）：只在区块内增删改，区块外原样保留。
2. 安全写入：写前备份 `config.bak.<时间戳>` → 临时文件 → 原子替换 → `ssh -G` 反向校验。
3. 变更预览：落盘前展示 diff（`similar`），确认后再写。
4. 密钥生成：ed25519 默认，路径 `id_ed25519_<备注名>`，**强制随机强口令存入 vault**（落地 M0 默认方案）。
5. 私钥落盘策略：默认模式（带口令私钥投放到 `~/.ssh`）与严格模式（仅投放 `.pub`，私钥留 vault）二选一，按身份可配。
6. icacls 收紧 ACL（落地 M0-4）：生成/导入投放时自动收紧。
7. 公钥展示 + 一键复制 + 打开 GitHub SSH 设置页。
8. 新建身份五步向导（含 §3.9 归属标识录入，`ssh -T` 后自动预填账号名）。
9. 操作历史/审计记录每次写入。

**新增依赖**：`similar`。

**交付物**：不开终端即可创建新身份、生成密钥、写 config、验证连接的完整闭环。

**验收标准**：
- 新建身份后 `~/.ssh/config` 仅托管区块被修改，用户手写内容与注释完好。
- `ssh -G <别名>` 校验解析结果与预期一致。
- 误操作可从自动备份恢复。
- 生成的密钥带口令；投放的私钥 ACL 已收紧。

**风险**：改坏用户 config——由托管区块 + 备份 + 原子写 + 反向校验四重防护。

### M4 · ssh-agent 管理与自动解锁（约 1 周）

**目标**：让密钥自动、无感地进 agent，落地 M0 的双路径与 askpass 方案。

**前置**：M3。

**任务清单**：
1. agent 服务管理：查询状态；一次性 UAC 提权启用并设自启（落地 M0-5 发现的"服务被禁用"）。
2. **免提权 fallback**：用 Git 自带 ssh-agent 作为普通进程运行并接管 `SSH_AUTH_SOCK`（M0 已验证可行）；界面明示当前用哪条路径。
3. askpass 辅助：从 vault 取口令，经 `SSH_ASKPASS`+`REQUIRE=force` 自动喂入（落地 M0-1）。
4. 严格模式加载：解密私钥 → `ssh-add -` 经 stdin 入 agent（落地 M0-2/3），关闭/锁定时卸载。
5. agent 列表**按指纹反查身份**（原生命令只给指纹路径）。
6. 加载/卸载/清空（`ssh-add`/`-d`/`-D`）。
7. 诊断项补全：权限过宽、孤儿 IdentityFile、Host 重名、agent 与 config 不一致；错误信息中文化 + 修复按钮。
8. 可选 Windows Hello 快速解锁（DPAPI 存 MK 副本，默认关闭）。

**新增依赖**：`windows`（platform 内）、`keyring`（可选）。

**交付物**：解锁应用后密钥自动进 agent、状态灯转绿、连接体检批量通过的应用。

**验收标准**：
- 服务被禁用时能走 Git fallback 完成加载。
- 带口令密钥全程无口令弹窗即加载成功。
- 严格模式下磁盘无私钥文件，`ssh -T` 仍成功。
- agent 列表能显示"这把 key 属于哪个身份"。

**风险**：两套 ssh/agent 混用不通——启动探测并锁定同一套工具链。

### M5 · 仓库管理与地址智能识别（约 1.5 周）

**目标**：解决笔记步骤 7–9（clone/remote/提交身份），实现复制地址即用；PAT 自动上传公钥。

**前置**：M4。

**任务清单**：
1. 仓库扫描：指定根目录（默认 `D:\coding_program`），限深 5 层，跳过 `node_modules/target/.venv`；增量、可中断。
2. 每仓库展示 remote URL→别名解析、仓库级 `user.name/email` 与身份是否一致。
3. **地址解析**：识别 HTTPS/SSH/浏览器地址栏(/tree /blob /pull)/裸 owner-repo/gh CLI/带端口/自建三段路径。
4. **身份推断**（按 §3.9 置信度链）：归属标识精确/通配 → 主机唯一 → 账号名 → 历史 → API → `git ls-remote` 实测兜底；输出推荐 + 依据 + 备选。
5. 归属标识管理：手动录入 / `ssh -T` 自动写 / PAT 拉取组织列表勾选导入；自动学习回填；冲突处理（优先身份/每次询问）。
6. 一键操作：改写别名地址复制、克隆向导（克隆后自动写仓库提交身份）、`git remote set-url` 修复。
7. 地址体检：扫描发现 remote 用 `github.com` 而非别名时给修复建议。
8. PAT 上传公钥：token 存 vault、日志脱敏、**可选（不填也能用）**、明示所需 `admin:public_key`、直达创建页。
9. 可选剪贴板感知（默认关闭，只匹配 Git 地址，不留痕）。

**新增依赖**：`reqwest`（rustls）、`url`。

**交付物**：粘贴任意仓库地址→自动判定身份→给出别名地址/一键克隆；仓库身份体检与一键修复；PAT 上传公钥。

**验收标准**：
- 从浏览器地址栏复制 `/tree/main/xxx` 能正确剥出 owner/repo。
- 已登记 owner 时纯本地查表命中、零网络。
- 自建三段路径 `bx4/vchangr-com/...` 能正确前缀匹配。
- 克隆后该仓库提交身份自动正确。

### v1.1 · 云同步（端到端加密）（约 2 周）

**目标**：加密异地备份 + 换机恢复（非实时协作）。加密方案已在 M1 定稿，此处只做落地。

**前置**：v1.0 发布。

**任务清单**：
1. `SyncBackend` trait + R2 与 S3 实现（S3 兼容，差异在 endpoint/region）。
2. 配置界面：endpoint/bucket/AK/SK/region/前缀 + 连接测试（探针对象读写删）。
3. 加密上传：`HKDF(MK,"sync-object")` 加密内容；**对象名 HMAC** 化；大小填充归档。
4. `manifest.enc` 索引：逻辑路径→对象名→版本→哈希；"先传对象后传 manifest"保证一致性。
5. 冲突：版本号 + `If-Match`；冲突不自动合并，留快照供选择；云端保留最近 N 版。
6. 换机恢复流程：填连接信息 → **输入恢复密钥** → 拉取解密 manifest → 选择性还原 → 重建 config/权限 → 设新访问密码。
7. 孤儿对象垃圾回收。

**新增依赖**：`aws-sdk-s3` 或 `reqwest`+SigV4、`hmac`。

**交付物**：能把加密数据集同步到用户自有 R2/S3，并在新机用恢复密钥还原。

**验收标准**：
- 云端对象名与内容均无明文信息（人工抽查）。
- 断网/中断后重试不产生损坏索引。
- 新机仅凭恢复密钥 + 桶凭据完成还原。

**风险**：SigV4 细节——优先用成熟 SDK。

## 第五部分 · 贯穿性工程规范

### 5.1 安全不变量（每次 PR 自检）
- 机密绝不跨 IPC 到前端；绝不进日志；用完 `zeroize`。
- 任何机密落盘必经 vault 加密；`~/.ssh` 投放的私钥必须带口令或走严格模式。
- 改系统状态前必产出可预览的命令/diff，并写审计日志。

### 5.2 测试策略
- **单元测试**：vault 加解密、KDF、恢复密钥编解码、config 解析与托管写入、地址解析、身份推断。
- **集成测试**（`src-tauri/tests`）：用一次性密钥在临时 HOME 下跑 keygen→config→agent→ssh -T（可对 github 只读认证尝试）。
- **前端**：关键交互与状态机（锁定态）测试。
- **回归基线**：`m0-crypto` 标定程序保留，作为加密栈回归参照。

### 5.3 错误处理与中文化
- Rust 侧 `thiserror` 定义领域错误；命令层映射为"中文可读信息 + 机器码 + 修复建议"。
- 所有面向用户文案走 `i18n/`，默认中文。

### 5.4 平台抽象纪律
- 所有平台相关操作收在 `platform/`；新增 macOS/Linux 只补实现。

### 5.5 版本控制与协作
- `git init` 后按里程碑开分支；每完成一个可运行切片提交。
- 提交信息用中文，标注所属里程碑。
