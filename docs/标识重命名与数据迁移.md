# 御钥师标识重命名：备份、迁移与安装更新

仓库、安装标识、本机数据目录和 SSH 托管标记已统一为 **git-keymaster**。这次改完后不会再改。旧版 `git-account-manager` 的数据不会被程序删除；新版首次启动会**拷贝**到新位置，旧副本留作备份。

请先备份，再安装新版。不要先卸旧版再装新版而不备份——工作空间（保险库）不在安装目录里，卸程序通常不会删它，但本机状态目录和 SSH 入口可能对不上。

完整对照与操作如下。

---

## 1. 新旧对照

| 项目 | 旧 | 新 |
|---|---|---|
| GitHub 仓库 | `ice-juice/git-identity-manager-app` | `ice-juice/git-keymaster-app` |
| 安装包文件名 | 早期曾用 `git-account-manager_*` | 已是 `Git.Keymaster_*`（不变） |
| 界面名称 | 御钥师 / Git Keymaster | 不变 |
| 可执行文件 | `git-account-manager.exe` | `git-keymaster.exe` |
| 应用标识（安装身份） | `com.jeck.gitaccountmanager` | `com.jeck.gitkeymaster` |
| 本机状态目录（Windows） | `%APPDATA%\git-account-manager\` | `%APPDATA%\git-keymaster\` |
| SSH 镜像 | `~/.ssh/git-account-manager.config` | `~/.ssh/git-keymaster.config` |
| `~/.ssh/config` Include | `Include git-account-manager.config` | `Include git-keymaster.config` |
| 托管区块标记 | `managed by git-account-manager` | `managed by git-keymaster` |
| agent 套接字 / pid | `~/.ssh/agent/git-account-manager` | `~/.ssh/agent/git-keymaster` |
| agent 环境脚本 | `git-account-manager-agent.env.ps1/.sh` | `git-keymaster-agent.env.ps1/.sh` |
| 开发者本机源码目录 | `D:\coding_program\local-git-account-manage` | `D:\coding_program\git-keymaster-app` |

**不会自动改名、也不该改的：**

- 你当初选定的**工作空间目录**（保险库，里面是加密身份、密钥、仓库登记）。路径写在本机 `config.json` 的 `workspacePath`。
- 各 Git 仓库本身、远程地址、提交历史。
- 恢复密钥（`GAM1-...`）。它只在你自己的密码本 / 离线记录里。

---

## 2. 新版本会自动做什么

首次启动新版时（创建窗口之前）：

1. 若 `%APPDATA%\git-keymaster\config.json` **还不存在**，且旧目录存在 → **整目录拷贝**到新位置。旧目录不删。
2. 若 `~/.ssh/git-keymaster.config` 不存在、旧镜像存在 → 拷贝一份。
3. 若 `~/.ssh/config` 已经是本程序写入的 Include 入口（只有注释 + Include）→ 改写成新文件名。
4. 旧 agent 环境脚本存在、新文件还没有 → 拷贝。
5. 解锁并写入 SSH 之后：托管区块会按新标记重写；区块外的手写 Host 原样保留。
6. 旧版导出的 S3/R2 配置文件（`kind: git-account-manager-s3`）仍能导入。

自动迁移**不会**覆盖已经存在的新文件，也**不会**删除旧目录。确认新版一切正常后，再按第 7 节手工清理。

## 3. 更新前：完整备份

关掉御钥师。不要在程序运行时拷贝工作空间。

### 3.1 最稳妥：先在旧版里导出官方备份

旧版还打得开时：

1. 解锁工作空间。
2. 使用应用内的**离线加密备份**（`.gambackup`），设一个独立备份密码。
3. 若已配置云同步，再做一次推送，确认云端快照是新的。
4. 把 `.gambackup` 拷到 U 盘或另一块盘，**不要只放在工作空间目录里**。

这是换机/回退时最完整的一份。下面的文件夹拷贝是双保险。

### 3.2 必须拷走的路径（Windows）

在资源管理器地址栏可直接粘贴。先建一个备份目录，例如 `D:\backup\keymaster-2026-09-10\`。

| 拷什么 | 典型位置 | 为什么 |
|---|---|---|
| 工作空间整夹 | 打开 `%APPDATA%\git-account-manager\config.json`，看 `workspacePath` | 身份、密钥、仓库登记、SSH 正本都在这里 |
| 本机状态目录 | `%APPDATA%\git-account-manager\` | 工作空间路径、窗口、代理、更新源、云同步本机偏好 |
| SSH 入口 | `%USERPROFILE%\.ssh\config` | 系统真正读取的入口 |
| SSH 镜像 | `%USERPROFILE%\.ssh\git-account-manager.config` | 旧版写入的 Include 目标 |
| SSH 备份 | `%USERPROFILE%\.ssh\config.bak.*` | 程序改写前留下的备份 |
| 恢复密钥 | 你自己的密码管理器 / 纸质记录 | 没有它，忘了访问密码就打不开保险库 |

工作空间路径因人而异。若 `config.json` 里没有、或文件不在，回忆你初始化时选的目录（常见是单独的数据盘文件夹，而不是 `C:\Program Files`）。

PowerShell 示例（先改工作空间路径）：

```powershell
$stamp = Get-Date -Format "yyyyMMdd-HHmm"
$dest = "D:\backup\keymaster-$stamp"
New-Item -ItemType Directory -Force -Path $dest | Out-Null

# 1) 本机状态
Copy-Item "$env:APPDATA\git-account-manager" "$dest\appdata-old" -Recurse -Force

# 2) 工作空间：把下面改成你的 workspacePath
Copy-Item "D:\你的工作空间目录" "$dest\workspace" -Recurse -Force

# 3) SSH
New-Item -ItemType Directory -Force -Path "$dest\ssh" | Out-Null
Copy-Item "$env:USERPROFILE\.ssh\config" "$dest\ssh\config" -ErrorAction SilentlyContinue
Copy-Item "$env:USERPROFILE\.ssh\git-account-manager.config" "$dest\ssh\" -ErrorAction SilentlyContinue
Copy-Item "$env:USERPROFILE\.ssh\config.bak.*" "$dest\ssh\" -ErrorAction SilentlyContinue
Copy-Item "$env:USERPROFILE\.ssh\git-keymaster.config" "$dest\ssh\" -ErrorAction SilentlyContinue

# 4) 若已有官方备份，也放进去
# Copy-Item "D:\path\to\xxx.gambackup" "$dest\"
```

拷完后确认：`$dest\workspace` 里能看到保险库文件（通常有加密库、`ssh\`、`keys\` 等），`$dest\appdata-old\config.json` 能打开且含 `workspacePath`。

### 3.3 macOS / Linux

- 本机状态：旧版若在 Windows 的 `%APPDATA%` 逻辑下运行过便携包，可能落在临时目录；正常桌面安装仍以应用写入的 `config.json` 为准。备份时把整个本机状态目录和工作空间一起拷走。
- SSH：`~/.ssh/config`、`~/.ssh/git-account-manager.config`，以及 `~/.ssh/config.bak.*`。

### 3.4 不要指望这些能当备份

- 只卸载/重装安装包：工作空间一般还在，但本机状态目录可能对不上新标识。
- 只备份 `Program Files` 里的安装目录：那里没有保险库。
- 只备份公钥：严格模式下磁盘可能没有私钥副本，必须靠工作空间或 `.gambackup`。

## 4. 安装与更新

应用标识变了，Windows / macOS 会把它看成**新应用**。不要依赖旧版「检查更新」完成这一跳；请下载新安装包。

发布页：<https://github.com/ice-juice/git-keymaster-app/releases>

### 4.1 已安装旧版

1. 按第 3 节备份，并确认恢复密钥还在。
2. 退出旧版御钥师（托盘图标也要退出）。
3. **先不要卸载旧版**（出问题还能开回去）。
4. 安装新版 `Git.Keymaster_*`（Windows 推荐 `*-setup.exe`）。
5. 从开始菜单打开**新的**御钥师（可执行文件应是 `git-keymaster`）。
6. 应能看到原来的工作空间路径；用原访问密码或恢复密钥解锁。
7. 解锁后做第 5 节核对。
8. 核对通过后，再到「应用和功能」里卸载**旧的**那一条（标识仍是旧的）。不要勾选任何「删除用户数据」（一般也没有这项）。
9. 工作空间目录不要删。

若开始菜单出现两个「御钥师」，先用新的。旧的卸掉即可。

### 4.2 新机器或旧版已经卸掉

1. 安装新版。
2. 打开后应提示初始化或选择工作空间。
3. 若你有 `.gambackup`：用「导入备份」，输入备份密码，预览资产后再合并。
4. 若你有完整文件夹备份：把工作空间拷回原路径（或任意新路径），启动后在界面里指向该目录并解锁。
5. 若本机状态也要恢复：把备份的 `appdata-old` 内容拷到 `%APPDATA%\git-keymaster\`（新版目录），再启动。不要和正在运行的程序抢写。

### 4.3 开发者本机源码目录

这只影响你自己 clone 的文件夹名，不影响用户数据。

```powershell
# 先关掉占用该目录的编辑器 / 终端
Rename-Item "D:\coding_program\local-git-account-manage" "D:\coding_program\git-keymaster-app"
cd D:\coding_program\git-keymaster-app
git remote -v
# 应为 git@github-ice-juice:ice-juice/git-keymaster-app.git
```

然后用新路径重新打开工作区。

## 5. 首次启动后核对

按顺序做，全部通过再删旧文件。

1. **能解锁**：原密码或恢复密钥可用。身份列表与改名前一致。
2. **本机配置在新目录**：存在 `%APPDATA%\git-keymaster\config.json`，且 `workspacePath` 仍指向你的工作空间。
3. **SSH 入口已换新名**：`%USERPROFILE%\.ssh\config` 里是 `Include git-keymaster.config`，且存在 `git-keymaster.config`。
4. **git 还能推**：打开一个已绑定身份的仓库，`git fetch` / `git push` 不再要你选错账号。失败时先看 `ssh -T git@你的别名`。
5. **云同步（若在用）**：设置里仍有 R2/S3 配置；拉一次、推一次，不报「找不到本机配置」。
6. **更新源**：设置 → 关于与更新，仓库为空时应显示 `ice-juice/git-keymaster-app`。

任一失败：不要删旧目录，改走第 6 节。

## 6. 自动迁移失败时的手动步骤

先退出新版。

### 6.1 新版找不到工作空间 / 当成空白

1. 打开备份里的 `appdata-old\config.json`，复制 `workspacePath`。
2. 确认该文件夹还在，且你没有改过里面的保险库文件。
3. 把旧本机目录拷到新位置（新位置没有 `config.json` 时才整夹覆盖）：

```powershell
Copy-Item "$env:APPDATA\git-account-manager\*" "$env:APPDATA\git-keymaster\" -Recurse -Force
```

4. 再启动。若仍空，在初始化界面「打开已有工作空间」指到备份的 workspace。

### 6.2 解锁成功但 git 走错账号 / 认证失败

1. 打开 `%USERPROFILE%\.ssh\config`。
2. 若仍是 `Include git-account-manager.config`，改成：

```
# git-keymaster：真实 SSH 配置在工作空间，请勿在此文件编写 Host。
Include git-keymaster.config
```

3. 若没有 `git-keymaster.config`：

```powershell
Copy-Item "$env:USERPROFILE\.ssh\git-account-manager.config" `
  "$env:USERPROFILE\.ssh\git-keymaster.config"
```

4. 回到应用解锁一次（会重写镜像）。新开一个终端再试 `ssh -T`。

### 6.3 只有 `.gambackup`、本机目录已经没了

1. 安装新版，初始化一个**临时**空工作空间（或直接走导入）。
2. 导入 `.gambackup`，用备份密码解密预览，确认身份数量后再合并。
3. 按提示重新部署私钥到本机 `~/.ssh`。
4. 用恢复密钥仅在「忘了访问密码」时使用，不能代替备份文件。

### 6.4 新旧两个御钥师同时开着

关掉两个（含托盘）。新版会认新旧两把单实例锁；不要双开，以免抢写工作空间。

---

## 7. 确认无误后清理旧文件

只在第 5 节全部通过之后做。建议再留一周再删。

可删：

```text
%APPDATA%\git-account-manager\
%USERPROFILE%\.ssh\git-account-manager.config
%USERPROFILE%\.ssh\git-account-manager-agent.env.ps1
%USERPROFILE%\.ssh\git-account-manager-agent.env.sh
%USERPROFILE%\.ssh\agent\git-account-manager
%USERPROFILE%\.ssh\agent\git-account-manager.pid
```

以及「应用和功能」里残留的旧御钥师安装项。

不要删：

```text
工作空间目录本身
%APPDATA%\git-keymaster\
~/.ssh/config
~/.ssh/git-keymaster.config
你的 .gambackup 与恢复密钥
```

---

## 8. 回退到旧版

1. 退出新版。
2. 安装旧版安装包（若还留着）。
3. 把备份的 `appdata-old` 拷回 `%APPDATA%\git-account-manager\`。
4. 把备份的 `config` / `git-account-manager.config` 拷回 `~/.ssh\`。
5. 工作空间若被改过，用备份的 workspace 覆盖（先把当前目录改名，再拷回，不要直接混）。
6. 打开旧版解锁。核对 git 后再决定是否卸新版。

新版写入过的 `git-keymaster.config` 可以留着，旧版不会读它。

## 9. 常见问题

**卸旧版会不会删保险库？**  
不会。保险库在你选的工作空间目录，不在安装目录。仍要先备份。

**应用内更新能不能从旧版直接升上来？**  
不建议。标识和默认仓库都变了，请从 [Releases](https://github.com/ice-juice/git-keymaster-app/releases) 装新包。

**云端数据要不要迁？**  
对象内容仍用同一把工作空间主密钥。换的是本机标识，不是云端格式。导入旧 `kind` 的 S3 配置文件即可。若两端一台已升、一台未升，先升两端再同步，避免旧端把新标记的 SSH 区块当成「非托管」原文。

**忘记访问密码？**  
用恢复密钥重置。没有恢复密钥、也没有 `.gambackup`，加密库无法解密。

**开发目录改名后 Cursor / git remote 怎么办？**  
按 4.3 改文件夹名，用新路径打开仓库。`origin` 应为 `ice-juice/git-keymaster-app`。
