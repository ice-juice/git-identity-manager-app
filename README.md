# Git 多账号管理器 (Git Account Manager - GAM)

> **优雅、安全、开箱即用的本地 Git 多身份与 SSH 密钥管理工作站**  
> 专为需要在同一台计算机上安全管理多个 GitHub / GitLab / 自建 Git 服务器账号的开发者设计。

---

## 🎯 为什么需要它？

在日常开发中，我们经常需要在同一台机器上切换不同的 Git 身份（例如个人开源账号、公司企业账号、兼职外包账号、自建私有代码库等）。手工维护 `~/.ssh/config`、多个密钥对、`ssh-agent` 服务以及每个仓库的提交邮箱极其容易出错：
- ❌ 手动敲命令生成密钥容易命名混乱，口令随意记录在不安全的地方；
- ❌ `~/.ssh/config` 别名配置繁琐，漏配 `IdentitiesOnly yes` 会导致认证失败或被服务商拉黑；
- ❌ `ssh-agent` 服务在 Windows 下经常停止，每次重启都需要重新键入口令；
- ❌ 提交代码时经常漏设局部 `user.name` 与 `user.email`，导致商业代码挂上个人邮箱；
- ❌ 换机迁移时私钥拷贝不安全，缺乏系统级的安全加密备份与恢复机制。

**Git 多账号管理器** 彻底终结了这些烦恼。通过直观紧凑的桌面 UI、纯本地端到端加密、智能地址识别、自动化密钥注入与无缝多账号隔离，让多身份管理变得如同单账号般丝滑。

## 🌟 核心特性全景

### 1. 军工级本地加密工作空间 (Vault)
- **双信封加密模型**：数据主体由随机生成的 256 位主密钥（MasterKey）保护；主密钥分别被**日常访问密码**与**高强度恢复密钥**双重信封封装。
- **Argon2id + XChaCha20-Poly1305**：抵抗暴力破解与彩虹表攻击，加解密均在 Rust 原生内存执行，用完立即使用 `zeroize` 安全清零，绝无明文泄露风险。
- **会话与免密宽限期**：支持设定开机免验证天数（0–30 天），兼顾安全性与日常极速开发体验。

### 2. 身份总览与实时体检 (Overview & Health)
- **四维状态健康灯**：每项身份实时展示【密钥有效性】、【Config 配置映射】、【Agent 驻留状态】与【远程连接 (ssh -T)】全套体检指标。
- **一键 SSH 连通性测试**：单项或批量实时连通 GitHub / GitLab 测试，即刻确认免密认证是否成功，告别终端猜错。
- **安全编辑与仓库防误删校验**：修改关键别名时自动检查已绑定的本地仓库，防范断链风险并提供二次确认保护。

### 3. SSH 密钥与配置自动化 (Keys & Config)
- **零终端生成与导入**：一键生成现代化 Ed25519 强密钥，自动生成随机保护口令并托管入库。
- **自动安全部署**：私钥统一投放至工作空间受控目录，Windows 原生 `icacls` 自动收紧权限，彻底解决 OpenSSH `UNPROTECTED PRIVATE KEY FILE` 报错。
- **透明式配置写入**：所有落盘操作均提供 Diff 差异实时预览与备份回滚能力。

### 4. SSH Agent 无缝托管 (Agent)
- **开机自启与免输密加载**：应用解锁后，私钥自动解密并通过安全管道注入 `ssh-agent`，日常 `git push/pull` 无需再手动弹窗输密。
- **双工具链智能探测与 Fallback**：探明 Windows 原生 OpenSSH 与 Git for Windows 内置工具链，免提权模式自动兼容。

### 5. 仓库管理与智能地址识别 (Repos & Smart Clone)
- **全形态地址智能识别**：支持识别 HTTPS、SSH、浏览器地址栏 URL、裸 Owner/Repo 等各类地址，依据归属标识（Owner）智能推荐对应身份并秒级改写为别名地址。
- **独立仓库管理工作台**：集中管理所有已绑定的本地仓库，支持一键打开目录、检测别名合规性与在线切换 Remote URL。
- **克隆与初始化向导**：自动判断目标目录状态（全新克隆 vs 已存在项目初始化），操作完成后自动登记到管理数据库并写入正确的 `user.name` / `user.email`。

### 6. M6 本地离线加密备份与换机迁移 (Offline Backup)
- **单文件便携归档 (.gambackup)**：支持将全部身份、密钥元数据、本地仓库关联以及私钥副本打包导出为单一文件。
- **独立密码保护**：导出时设置独立备份密码，通过 Argon2id 重新派生密钥加密，安全脱离原电脑在全新设备上一键还原。
- **安全导入预览**：导入时可先解密查看资产清单明细，确认后自动合并并重新部署工作空间私钥。

### 7. v1.1 端到端零知识加密云端同步 (E2EE Cloud Sync)
- **S3 / Cloudflare R2 原生兼容**：自带无额外负担的 AWS SigV4 客户端，支持 Cloudflare R2、AWS S3、MinIO 等任意兼容对象存储。
- **出机即密文**：所有数据均在出机前使用工作空间主密钥与 `XChaCha20-Poly1305` 加密，云服务商无法查阅任何内容。
- **对象名 HMAC 混淆**：云端所有文件名均通过 `HMAC-SHA256` 散列化存储，零明文泄露，甚至无法推断账号名称或仓库路径。
- **原子事务一致性**：坚持“先传加密对象，最后提交 Manifest 清单”，断网或异常中断不损坏既有快照。

## 🚀 快速上手与运行

### 环境要求
- **操作系统**：Windows 10 / 11 64-bit (亦支持 Linux / macOS 构建)
- **开发依赖**：
  - Node.js >= 20 (推荐使用 nvmd / nvm)
  - Rust >= 1.77.2 (包含 `cargo` 工具链)
  - Visual Studio C++ 生成工具 (Windows Desktop)

### 常用命令

```bash
# 1. 克隆代码仓库
git clone <repo_url>
cd local-git-account-manage

# 2. 安装前端依赖
cd app
npm install

# 3. 启动桌面开发调试窗口
npm run tauri dev

# 4. 执行单元测试
cd src-tauri
cargo test

# 5. 构建生产分发安装包 (MSI / NSIS)
cd ../
npm run tauri build
```

## 🔒 安全设计与常见问题

### Q1: 如果忘记了访问密码怎么办？
A: 在工作空间初始化时，系统会生成一份全球唯一的 **恢复密钥 (Recovery Key)**（格式形如 `GAM1-...`）。请在初次创建时将其记录并保存在密码管理器或安全离线媒介中。使用恢复密钥可在任何时候重置访问密码或在新机还原工作空间。

### Q2: 为什么云端同步要求使用 R2 或 S3？
A: 遵循“用户掌控自身数据”的去中心化隐私原则。我们不设立中心化数据服务器，用户只需将自有 Cloudflare R2（每月提供大量免费存储与零流出流量费）或 AWS S3 凭证填入应用，即可实现全球加密异地备份，且享有真正的端到端零知识隐私保护。

### Q3: 严格模式（Strict Mode）与普通模式的区别？
A: 
- **默认普通模式**：私钥以强加密格式存入工作空间 `keys/`，并投放至 `ssh-keys/` 供 OpenSSH 调度，权限被严格锁死在当前 Windows 登录用户。
- **严格模式**：磁盘完全不留私钥明文或带口令私钥，仅在解锁时将私钥加载进 `ssh-agent` 内存，磁盘仅存 `.pub` 公钥，极大提高极端情况下的物理防拷保护。
